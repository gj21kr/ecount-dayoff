# 팀 휴가 대시보드

AI/SW팀 휴가를 월간·주간 캘린더와 목록으로 표시하는 로컬 웹앱입니다. 회의와 Outlook 수집은 비활성화되어 있습니다.

> **이 저장소에는 eCount 로그인·웹 조회 수집기가 없습니다.**
> PDF 또는 이미 만들어진 JSON 저장본을 읽어 표시합니다. eCount 계정 정보를 입력하는 설정이나 API 키 연동도 구현되어 있지 않습니다.
> 저장소를 복제하고 eCount에 로그인하는 것만으로 자동 수집이 시작되지는 않습니다.

## 기능과 별도 준비 사항

| 기능 | 저장소에 포함 | 별도 준비 |
|---|---|---|
| 휴가 캘린더·팀 필터·목록·반차 표시 | 예 | 팀원 명단 |
| PDF 읽기·중복 제거·자정 갱신 | 예 | 지원 형식의 PDF |
| eCount 조회 저장본 검증·표시 | 예 | 지정 스키마의 JSON 작성 |
| eCount 로그인·근태현황 웹 조회 | 아니요 | 사용자의 브라우저 작업 또는 별도 수집기 |
| 매일 오전 8시 eCount 확인 | 아니요 | 로컬 에이전트 자동화 또는 별도 예약 작업 |
| 사용자 인증·접근 권한 관리 | 아니요 | 네트워크/인증 구성 |

## 1. 로컬 실행

Docker Engine과 Docker Compose v2가 필요합니다. Windows에서는 Linux 컨테이너를 실행할 수 있는 Docker Desktop을 사용합니다. 호스트에 Python이나 Node.js 패키지를 설치할 필요는 없습니다.

Windows PowerShell 예시:

```powershell
git clone https://github.com/gj21kr/ecount-dayoff.git
Set-Location ecount-dayoff
New-Item -ItemType Directory -Force .credentials, .credentials/imports, .credentials/data | Out-Null
Copy-Item examples/teams.json .credentials/teams.json
```

`.credentials/teams.json`을 편집한 뒤 실행합니다. 기본 로컬 실행에는 `.env`가 필요하지 않습니다.

```powershell
docker compose up -d --build
```

접속: [http://127.0.0.1:8787](http://127.0.0.1:8787)

데이터를 아직 넣지 않았다면 빈 캘린더가 정상입니다. 운영하려면 PC와 Docker가 실행 중이어야 합니다.

```powershell
# 로그 확인
docker compose logs --tail 100 dashboard

# 중지 / 다시 시작
docker compose stop
docker compose up -d
```

## 2. 팀원 명단 설정

`.credentials/teams.json`에는 eCount에 표시되는 실제 이름을 입력합니다. 아래는 가상 인물 예시입니다.

```json
{
  "teams": [
    {"id": "AI", "name": "AI팀", "members": ["가상연구원", "가상개발자"]},
    {"id": "SW", "name": "SW팀", "members": ["가상팀원"]}
  ],
  "aliases": {
    "Example Developer": "가상개발자",
    "가상 개발자": "가상개발자"
  }
}
```

- 현재 팀 ID와 화면은 `AI`, `SW`를 지원합니다. 임의의 팀 추가는 코드 변경이 필요합니다.
- 별칭의 대상은 반드시 명단의 이름이어야 합니다. 별칭은 팀 판정과 eCount/PDF 대조에 사용합니다.
- PDF에서 명단 밖의 이름은 미분류로 표시됩니다. eCount JSON의 명단 밖 이름은 검토 대상으로 보류됩니다.
- 명단 설정은 시작 시 읽으므로 수정 후 `docker compose restart dashboard`를 실행합니다.

## 3. eCount 데이터 준비

본인 계정으로 eCount에 로그인하고 필요한 직원의 근태 자료를 조회할 권한이 있어야 합니다. 비밀번호나 브라우저 쿠키를 이 프로젝트에 복사할 필요는 없습니다.

아래 두 방법 중 하나를 사용할 수 있으며, 함께 사용하는 경우 같은 휴가는 서버에서 중복 제거합니다.

### 방법 A: PDF 가져오기

1. eCount에서 휴가 신청·전자결재 문서 중 **근태전표와 근태일자 표가 있는 문서**를 PDF로 저장합니다.
2. PDF를 `.credentials/imports/`에 넣습니다. 하위 폴더도 읽습니다.
3. 대시보드의 **새로고침**을 누릅니다. 이후 PDF 폴더는 매일 한국 시간 00:00에 다시 확인합니다.

지원 범위:

- 텍스트를 추출할 수 있는 PDF여야 합니다. 스캔 이미지 OCR은 지원하지 않습니다.
- `근태전표`, `근태일자` 항목과 이름·근태일자·휴가 유형·일수 순서의 행을 해석합니다.
- 임의의 eCount 보고서나 모든 전자결재 양식을 지원하는 것은 아닙니다.
- 암호화 PDF, 20 MB 초과 또는 100페이지 초과 문서는 지원하지 않습니다.
- 취소·반려 표시나 불명확한 행은 **데이터 연결 → 확인이 필요한 문서**에서 확인합니다.
- 실제 휴가일은 **근태일자**입니다. 기안일자나 전표일자로 대체하지 않습니다.
- 이 파서는 문서를 읽으며, 최종 결재 승인 여부를 독립적으로 검증하지는 않습니다.

원본은 읽기 전용입니다. 파일이 사라지거나 읽기 실패한 경우 기존 휴가를 자동 취소하지 않고 마지막 자료와 검토 항목을 유지합니다.

### 방법 B: 근태현황 조회 결과를 JSON으로 가져오기

웹 조회 자체는 수동 작업 또는 별도 도구로 수행해야 합니다.

1. eCount의 **근태현황**에서 원하는 기간과 팀원을 선택합니다.
2. 이 저장본 형식의 기준은 **상태: 확인**, **근태 항목: 연차**입니다. 실제 권한·화면에 맞게 해당 조건을 확인합니다.
3. 모든 페이지를 확인하고 **근태일자, 사원명, 휴가 유형, 일수, 명시된 오전/오후**를 읽습니다.
4. 아래 스키마로 UTF-8 JSON을 작성해 `.credentials/data/ecount-snapshot.json`에 저장합니다.
5. 화면은 약 60초마다 API를 다시 조회합니다. 브라우저를 새로고침해도 확인할 수 있습니다.

다음은 실제 직원 정보가 없는 예시입니다. `person`은 자신의 명단과 맞아야 하며, 조회 시각과 기간도 실제 조회에 맞춰 작성해야 합니다.

```json
{
  "version": 1,
  "capturedAt": "2026-10-23T08:00:00+09:00",
  "rangeStart": "2026-01-01",
  "rangeEnd": "2027-01-01",
  "statusFilter": "확인",
  "rows": [
    {
      "date": "2026-10-26",
      "person": "가상연구원",
      "type": "연차",
      "amount": 1,
      "slot": null
    },
    {
      "date": "2026-10-27",
      "person": "가상개발자",
      "type": "반차",
      "amount": 0.5,
      "slot": null
    }
  ]
}
```

| 필드 | 의미·제약 |
|---|---|
| `capturedAt` | 실제 조회 성공 시각. 한국 시간 오프셋 `+09:00` 포함 |
| `rangeStart` / `rangeEnd` | 시작일 포함, **종료일 제외**. 전체 2026년이면 종료일은 2027-01-01 |
| `statusFilter` | 현재 형식에서는 `확인`만 허용 |
| `date` | 실제 근태일자. 조회 범위 안에 있어야 함 |
| `person` | 설정 명단의 이름 또는 등록한 별칭 |
| `type` | `연차`, `반차`, `오전반차`, `오후반차` |
| `amount` | JSON 숫자 `1` 또는 `0.5`. 여러 날짜는 날짜별 행으로 작성 |
| `slot` | 명시된 오전은 `am`, 오후는 `pm`, 미명시는 `null` |

`오전반차`는 `slot: "am"`, `오후반차`는 `slot: "pm"`이어야 하며, 명시된 시간대와 반차 유형은 일수 0.5와 일치해야 합니다.
오전·오후가 없는 0.5일은 원본 `slot: null`을 유지합니다. 화면에서만 오전반차로 임시 표시하고 **시간대 미명시 · 오전으로 임시 표시**를 병기합니다.

저장본은 최대 2 MiB, 10,000행, 조회 기간은 최대 1,830일입니다. 형식 오류나 잘못된 행은 검토 대상으로 표시됩니다.
개인 사유·사원번호·비밀번호·쿠키는 저장하지 않습니다.

이 파일은 누적 추가 로그가 아니라 조회 범위 전체의 저장본입니다. 일부 페이지 또는 변경분만으로 전체를 덮어쓰지 마세요. 별도 수집기를 작성한다면 조회 완료 후 임시 파일을 원자적으로 교체하고, 실패 시 기존 정상 파일과 성공 시각을 유지해야 합니다.

## 4. 오전 8시 확인을 재현하려면

원래 운영 환경의 오전 8시 확인 예약은 **Codex 앱의 로컬 자동화**입니다. 이 저장소에는 해당 자동화나 브라우저 세션이 포함되지 않으며, 예약 등록이 무인 로그인·정시 수집 성공을 보장하지도 않습니다.

동일한 흐름을 원하는 사용자는 자신의 환경에서 다음 작업을 별도로 설정해야 합니다.

1. 브라우저 조작이 가능한 에이전트 환경에서 본인 eCount 계정으로 로그인합니다.
2. 매일 08:00 **Asia/Seoul** 실행을 예약합니다.
3. 위의 조회 조건과 팀원 설정으로 전체 결과를 읽고, 위 JSON 형식으로 비공개 저장본을 갱신하도록 지시합니다.
4. 수동 시험 실행으로 근태일자·조회 범위·행 수·중복 제거·대시보드 반영을 확인합니다.
5. 로그인 만료나 추가 인증이 필요하면 사용자에게 알리고 이전 저장본을 유지하도록 합니다.

별도 자동화에 사용할 지시문 예시:

> 매일 한국 시간 오전 8시에 지정 프로젝트의 .credentials/teams.json을 읽어 조회할 팀원을 확인한다. 본인 계정으로 접근 가능한 eCount 근태현황에서 설정한 기간 전체, 상태 확인, 연차 항목을 조회한다. 모든 페이지를 확인한 뒤 실제 근태일자 기준으로 README의 JSON 스키마를 작성해 .credentials/data/ecount-snapshot.json을 원자적으로 교체한다. 원본에 없는 오전·오후를 추정해 저장하지 않는다. 조회 실패나 로그인 조치가 필요한 경우 이전 정상 저장본과 성공 시각을 유지하고 알린다. 정상이며 변경이 없으면 알리지 않는다. 실제 개인정보는 .credentials 밖의 코드·문서·스크린샷에 넣지 않는다.

이 문구는 설정 참고용이며 실행 가능한 수집 스크립트가 아닙니다. 일반 작업 스케줄러만 등록해도 브라우저 조회가 구현되지는 않습니다. 다른 에이전트를 사용하려면 별도의 수집기와 인증·예약 실행 구성을 마련해야 합니다.

앱의 **새로고침** 버튼은 PDF를 다시 읽습니다. eCount 웹사이트를 조회하거나 JSON 저장본을 새로 생성하지 않습니다. JSON의 마지막 성공 시각은 실제 조회 성공 때만 변경해야 합니다.

## 5. 비공개 파일과 사내 배포

개인정보와 운영 설정은 Git 및 Docker 빌드에서 제외된 `.credentials/`에 둡니다.

| 경로 | 용도 |
|---|---|
| `teams.json` | 실제 팀원 명단·이름 별칭 |
| `imports/` | PDF 입력 |
| `data/` | 휴가 저장본·상태·처리 이력 |
| `artifacts/` | 실제 데이터가 보이는 스크린샷 |
| `compose.private.yaml` | 사내 IP·외부 폴더 경로 등 로컬 배포 설정 |

`.gitignore`는 암호화나 접근 제어가 아닙니다. 폴더 전체 ZIP 업로드에는 제외 규칙이 적용되지 않습니다.

기본 배포는 로컬 주소만 엽니다. 외부 PDF 폴더를 연결하려면 `.credentials/compose.private.yaml`에 다음처럼 설정할 수 있습니다. 경로는 자신의 실제 경로로 바꿉니다.

```yaml
services:
  dashboard:
    volumes:
      - type: bind
        source: "C:/path/to/private/pdfs"
        target: /imports/eCount
        read_only: true
```

이 파일을 먼저 만든 다음 `.env.example`을 `.env`로 복사하고 `docker compose up -d`로 적용합니다. 기본 로컬 실행만 할 경우 이 과정은 생략합니다.

서비스에는 로그인 기능이 없습니다. 사내 IP로 포트를 열 경우 접근 가능한 사용자는 저장된 휴가를 볼 수 있습니다. 사내 공유는 별도로 바인딩·방화벽·접근 범위를 설정해야 합니다.

## 6. 확인과 문제 해결

- **빈 캘린더:** 현재 화면의 월과 입력 데이터 날짜, PDF 위치 또는 JSON 저장 위치를 확인합니다.
- **JSON 오류:** 이름·날짜 범위·숫자 일수·slot·상태 필터를 확인합니다.
- **PDF 오류:** 스캔본인지, 지원하는 근태전표 양식인지 확인합니다.
- **명단 수정 미반영:** 컨테이너를 재시작합니다.
- **조회 시각이 오래됨:** eCount 저장본은 자동 생성되지 않습니다. 별도 수집 작업과 로그인을 확인합니다.
- **PC 종료 중 예약 누락:** PDF는 서버 시작 시 다시 읽지만, eCount 예약 작업의 재시도는 별도 자동화가 담당합니다.

상태 확인:

```powershell
Invoke-RestMethod http://127.0.0.1:8787/api/health
```

health 성공은 서버 가동을 의미하며 eCount의 최신 조회 성공을 보장하지 않습니다. 데이터 연결 화면에서 출처별 상태와 조회 시각을 확인하세요.

가상 인물과 합성 입력을 사용하는 테스트:

```powershell
docker build -t ecount-dayoff-test .
docker run --rm --network none ecount-dayoff-test python -m pytest -q tests
```
